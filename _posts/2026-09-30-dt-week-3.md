After meeting with the client and getting back into the project, there are a few big problems we've identified.
- Workshops don't do anything
    - Workshops are supposed to be big projects involving multiple students
    - Right now, it's just an "isWorkshop" boolean that provides no functionality
    - To fix this issue, we need to adjust the schema so that students and projects have a "many-to-many" relationship
        - Currently students can have multiple projects, but not the other way around
        - I think we should introduce a model class called "Inclusions" that handles the various relationships between projects and students
        - This will provide more flexibility and functionality to workshops
- The client would like to be able to export data into Excel files
- Students need to be able to upload images to their projects
- Projects need School, SiteLocation, and ProjectType fields

The most important issue is updating the schema with the Inclusions model class because the schema is the skeleton of the project. I've started working on this Inclusions class, but this has turned out to be quite tedious because I have to almost every page.
